# Step 1 — Sidecar scaffold (Node + Express + HMAC + health)

**Goal:** Stand up the empty `sidecars/whatsapp-web/` Node service. TypeScript + Express, structured logging, HMAC request verification middleware, single `/health` endpoint. **No Baileys yet** — that lands in Step 2. The point of this step is to prove the deploy + secrets + HMAC contract works in isolation before any WhatsApp protocol code touches it.
**Track:** WhatsApp Unofficial (Baileys)
**Status:** Pending
**Depends on:** None.

---

## Scope

In-scope:

- **New top-level folder** `sidecars/whatsapp-web/` (sibling to `api/`, `app/`, `Flutter/`).
- **`package.json`** with locked dependencies (no `^` ranges on `@whiskeysockets/baileys` — pin exact version):
  - `express`, `pino`, `pino-pretty` (dev), `zod`, `axios`
  - `typescript`, `tsx`, `@types/express`, `@types/node` (dev)
  - **No Baileys yet** — Step 2 adds it.
- **`tsconfig.json`** — `"strict": true`, ES2022 target, NodeNext module, `outDir: "dist"`.
- **`src/index.ts`** — Express bootstrap: load config, mount logger, mount HMAC middleware, mount `/health` route, listen on `SIDECAR_PORT`.
- **`src/config.ts`** — env loader using `zod` schema. Reads `SIDECAR_PORT`, `SIDECAR_HMAC_SECRET`, `FASTAPI_BASE_URL`, `FASTAPI_HMAC_SECRET`, `LOG_LEVEL`, `STORAGE_DIR`. Fails fast at boot if any required var is missing.
- **`src/logger.ts`** — pino instance with redaction for `Authorization` header + `secret` field.
- **`src/auth.ts`** — two helpers + one middleware:
  - `verifyIncomingHmac(req)` — checks `X-Sidecar-Signature` header (`sha256=<hex>` of raw body) using `SIDECAR_HMAC_SECRET`. Constant-time compare. Returns 401 on mismatch.
  - `signOutgoing(body, secret)` — produces `sha256=<hex>` for outbound requests to FastAPI. Used in Step 3.
  - `hmacMiddleware` — Express middleware applied to all non-`/health` routes. Allows `GET /health` through unauthenticated.
- **`src/routes/health.ts`** — `GET /health` returns `{status: "ok", uptime_seconds, version}`. No auth.
- **`Dockerfile`** — multi-stage: builder runs `tsc`, runtime uses `node:22-alpine` + `dist/` only. `EXPOSE 4000`. `CMD ["node", "dist/index.js"]`.
- **`.gitignore`** — `node_modules`, `dist`, `storage/`, `*.log`.
- **`README.md`** in `sidecars/whatsapp-web/` documenting: env vars, local dev (`npm run dev`), Docker build, health check curl, where Step 2's Baileys session storage will live.
- **One smoke test** at `tests/auth.test.ts` (using `node:test` — no extra test framework dep): `signOutgoing` + `verifyIncomingHmac` round-trip, constant-time compare path, replay rejection (same payload + wrong signature → 401).

Out of scope:

- **Baileys, sessions, QR pairing** — Step 2.
- **`/send-text`, `/send-media`, event forwarder** — Step 3.
- **FastAPI integration** — Steps 4+.
- **CI workflow** for the sidecar — can land later; this step just gets the local-dev story working.
- **Secrets management** — uses plain `.env` for sidecar local dev. Production secret injection (SOPS pattern) is documented in the README but not wired (handled at deploy time, not by sidecar code).

## Plan

1. **Create folder**: `mkdir -p sidecars/whatsapp-web/{src/routes,tests}`.
2. **`package.json`** with `"type": "module"`, scripts: `dev` (tsx watch), `build` (tsc), `start` (node dist), `test` (node --test).
3. **`tsconfig.json`** strict mode, NodeNext modules.
4. **`src/config.ts`** — zod schema:
   ```ts
   const Env = z.object({
     SIDECAR_PORT: z.coerce.number().int().min(1).max(65535).default(4000),
     SIDECAR_HMAC_SECRET: z.string().min(32),
     FASTAPI_BASE_URL: z.string().url(),
     FASTAPI_HMAC_SECRET: z.string().min(32),
     LOG_LEVEL: z.enum(["debug","info","warn","error"]).default("info"),
     STORAGE_DIR: z.string().default("./storage"),
   });
   export const config = Env.parse(process.env);
   ```
   Fail-fast: if env is missing, the `.parse` throws → process exits with the zod error before Express boots.
5. **`src/logger.ts`** — `pino({ level: config.LOG_LEVEL, redact: ['req.headers.authorization', 'req.headers["x-sidecar-signature"]', '*.secret', '*.token'] })`. Dev-only `pino-pretty` transport when `NODE_ENV !== 'production'`.
6. **`src/auth.ts`** — using `node:crypto`:
   ```ts
   import crypto from "node:crypto";
   export function sign(body: string, secret: string): string {
     return "sha256=" + crypto.createHmac("sha256", secret).update(body).digest("hex");
   }
   export function verify(body: string, header: string | undefined, secret: string): boolean {
     if (!header?.startsWith("sha256=")) return false;
     const expected = sign(body, secret);
     return crypto.timingSafeEqual(Buffer.from(header), Buffer.from(expected));
   }
   ```
   Middleware reads `req.rawBody` (set by `express.json({ verify: ... })`) and either calls `next()` or `res.status(401).end()`.
7. **`src/routes/health.ts`** — single `GET /health` returning JSON. No auth. Used by k8s readiness / docker-compose healthcheck.
8. **`src/index.ts`** — wire everything: import config (fails fast), create app, mount `express.json({ limit: "10mb", verify })`, mount `/health` BEFORE HMAC middleware, mount HMAC middleware, listen.
9. **`Dockerfile`** — two stages:
   ```
   FROM node:22-alpine AS builder
   WORKDIR /app
   COPY package*.json tsconfig.json ./
   RUN npm ci
   COPY src ./src
   RUN npm run build
   
   FROM node:22-alpine AS runtime
   WORKDIR /app
   ENV NODE_ENV=production
   COPY --from=builder /app/package*.json ./
   RUN npm ci --omit=dev
   COPY --from=builder /app/dist ./dist
   EXPOSE 4000
   CMD ["node", "dist/index.js"]
   ```
10. **`README.md`** — sections:
    - **Local dev**: copy `.env.example` → `.env`, `npm install`, `npm run dev`, curl `/health`.
    - **Required env vars**: documented with one-line purpose each.
    - **Production**: how secrets are injected (SOPS-decrypted env at runtime, same as FastAPI's `run.cmd`).
    - **Layout**: pointer to where Baileys session storage will live (`./storage/sessions/{org_id}/{session_id}/`).
    - **HMAC contract**: how FastAPI signs requests inbound + how sidecar signs requests outbound. Header name = `X-Sidecar-Signature` (inbound), `X-Fastapi-Signature` (outbound — set in Step 3).
11. **`tests/auth.test.ts`** — node:test cases:
    - Sign-then-verify returns true.
    - Sign-then-tamper returns false (one char flipped in signature).
    - Verify with wrong header prefix returns false.
    - Verify with empty header returns false.
12. **Root `.gitignore`** — append the 3 sidecar exclusions.

## Smoke

```
1. cd sidecars/whatsapp-web
2. cp .env.example .env
3. Fill .env with random 64-char hex for both HMAC secrets:
     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
4. npm install
5. npm run dev
6. In another shell:
     curl http://localhost:4000/health
     -> {"status":"ok","uptime_seconds":2,"version":"0.1.0"}
7. Try a non-health endpoint without HMAC (should return 401):
     curl -X POST http://localhost:4000/sessions
     -> {"error":"invalid signature"}
     (note: /sessions route doesn't exist yet — Express will 404 if HMAC
      passes. The 401 vs 404 distinction confirms HMAC middleware fires
      BEFORE the router.)
8. Send with a valid signature:
     BODY='{"foo":"bar"}'
     SECRET=<value from .env>
     SIG="sha256=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')"
     curl -X POST http://localhost:4000/sessions \
       -H "Content-Type: application/json" \
       -H "X-Sidecar-Signature: $SIG" \
       -d "$BODY"
     -> 404 (route not registered yet) — confirms HMAC accepts a valid sig
9. Docker build smoke:
     docker build -t whatsapp-web-sidecar:dev .
     docker run --rm -p 4000:4000 --env-file .env whatsapp-web-sidecar:dev
     curl http://localhost:4000/health  -> {"status":"ok",...}
```

## Risks

- **Node version drift.** Pinned to `node:22-alpine` in Dockerfile + `engines.node: ">=22"` in package.json. Local dev needs Node 22+ (Baileys 6.7+ requires it). Document in README.
- **HMAC secret rotation.** Today the secret lives in `.env`. Production deploys must wire SOPS injection — README explicitly flags this as "out of scope here, handled at deploy step".
- **`express.json` size limit.** Set to `10mb` to accommodate base64 media payloads from Step 3. If we ever stream uploads, revisit.
- **No CI** at this stage. Manual smoke is enough for a sidecar in the prototype phase. CI can be added once Steps 2–3 stabilise the contract.
